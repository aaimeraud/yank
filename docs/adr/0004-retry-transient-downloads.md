# Retry transient download failures with a fresh extraction

YouTube intermittently rejects an otherwise valid signed media URL with `HTTP Error 403: Forbidden` (yt-dlp issue 17395). Running the identical command moments later succeeds, so the failure is not a bad format, a missing challenge solver, or a bad cookie. Yank makes up to three attempts per download (two retries) with a 2s then 4s backoff, and every attempt re-runs extraction so it asks for a fresh signature instead of reusing the one that was rejected. Only transient HTTP and connection errors are retried; a permanent error such as an unsupported URL fails after one attempt. Pause and cancel are honoured during backoff, and a resume that lands in that window hands the row to a fresh task. A new `Retry failed (N)` action requeues every failed row for the cases where all three attempts lose.

Playlist videos download into the library folder named after the playlist. The folder is looked up by `video_id` on the backend, and unfiled videos fall back to `%(channel,uploader)s`. The previous template used `%(playlist_title|channel|uploader)s`, where `|` is not a fallback separator in yt-dlp, so it produced a literal `channel｜uploader` directory.
